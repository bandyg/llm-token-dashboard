# 02 Goals & Non-Goals

> Template v2

## Goals（要做什么）

- [ ] [P0] 在 Electron BrowserView 嵌入主流 LLM Provider 控制台页面（ChatGPT、Claude、Gemini、通义、文心、豆包、Kimi、DeepSeek 等），作为 DOM/OCR 抓取的统一载体。

- [ ] [P0] 在 BrowserView 当前页面叠一层可视化选区 UI，用户像截图工具一样所见即所得拖框圈选 OCR 识别区域，所选坐标自动回填并持久化（localStorage/SQLite），一次配置终身复用，彻底告别手填 x,y,w,h——这是产品的核心记忆点。

- [ ] [P0] 内置主流厂商官方 API 适配器（OpenAI、Claude、Gemini、阿里云百炼、百度千帆、火山引擎、智谱、月之暗面 等），通过 API Key 直接拉取已用 / 剩余额度与计费周期。

- [ ] [P0] 集成本地 PaddleOCR-js，对 BrowserView 截图按用户框选区域裁剪后进行离线 OCR 数字识别，覆盖无官方 API 或 API 不暴露额度信息的 Provider。

- [ ] [P0] 统一 Dashboard 集中展示所有 Provider 的已用 / 剩余额度、剩余百分比、刷新时间戳与异常状态，支持按 Provider 分组与排序。

- [ ] [P0] 采集失败以红字高亮提示，并提供 ≤3 次点击内可达的手动录入兜底入口（弹窗 → 数值输入 → 保存），保证任意 Provider 都能被纳入监控。

- [ ] [P1] 用户手动分批刷新机制：避免自动轮询触发 Provider 风控，刷新动作由用户主动触发，并可批量勾选多个 Provider 一次性刷新。

- [ ] [P1] 额度阈值告警：用户为每个 Provider 配置剩余额度阈值（百分比或绝对值），低于阈值时在 Dashboard 与系统通知中告警。

- [ ] [P1] 历史趋势存储与展示：本地 SQLite 记录每次刷新的额度快照，提供按日 / 周维度的折线图与环比变化。

- [ ] [P1] 选区配置可编辑与复制：用户可随时重新拖框覆盖旧坐标，并支持把同一选区配置复制到多账号 / 多 Profile。

- [ ] [P2] 导出历史用量为 CSV / JSON，便于用户自行做账单核对或二次分析。

- [ ] [P2] 深色 / 浅色主题切换，跟随系统外观。

## Non-Goals（明确不做）

- [x] 不做云端同步、不做账号服务、不开任何后端服务；所有数据、API Key、选区坐标仅保存在用户本机。

- [x] 不做自动后台轮询刷新；刷新必须由用户手动触发，分批节奏由用户掌控，避免触发 Provider 风控或 IP 封禁。

- [x] 不做 LLM 对话转发、API 代理、Token 计费网关等流量中转功能，本工具定位是「用量监控器」，不是「API 网关」。

- [x] 不做移动端、浏览器扩展、Web SaaS 版形态，仅交付桌面端 Electron 应用。

- [x] 不做破解、绕过或逆向无官方 API 厂商的鉴权机制，仅抓取用户在浏览器中已正常登录可见的页面 DOM / 截图。

- [x] 不做自动 OCR 训练或模型微调，使用现成 PaddleOCR-js 权重即可，不为识别准确率承担长期迭代承诺。

- [x] 不做多用户协作、权限管理、审计日志等企业级特性，保持单用户本地工具的轻量定位。

## 范围说明

- **平台边界**：仅交付 Windows / macOS / Linux 三大桌面平台的 Electron 包；不在 Web、移动端、Server 形态上做任何兼容。

- **Provider 覆盖边界**：以「有可见额度数字页面 + 至少可通过 DOM 或 OCR 抓取」的 Provider 为入选标准；纯命令行工具、无任何额度展示页面的 Provider 不在覆盖范围。

- **DOM 抓取适配边界**：各 Provider 控制台改版（class 名、DOM 结构变更）会导致抓取失效，灰区处理方式为——提供「选区 + 选择器」双向配置入口，失效时优先提示用户重新拖框或刷新选择器，而非由开发者远程热修。

- **OCR 性能边界**：PaddleOCR-js 在 CPU 上对小区域（典型选区 200×80px 以内）、高对比度数字场景识别足够；遇到低分辨率、艺术字体、强背景干扰时，识别失败需走红字提示 + 手动录入兜底，不承诺 100% 自动化。

- **手动录入兜底边界**：「≤3 次点击」定义为主流交互路径（Dashboard 红字 → 弹窗 → 输入数值 → 保存）最多三步可达；不计入首次启动引导、Provider 新增向导等冷启动流程。

- **刷新频率边界**：尊重各 Provider 控制台页面的自然刷新节奏（通常登录态下额度变更不会秒级发生），手动分批刷新默认建议间隔 ≥ 60 秒，但不做硬性强制。

- **数据持久化边界**：本地 SQLite 仅存储额度快照与选区配置，不记录用户聊天内容、API Key 明文以外的任何 Provider 用户行为数据；API Key 加密存储于本机 Keychain（Windows Credential Manager / macOS Keychain / libsecret）。
