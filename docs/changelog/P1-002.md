## 根因复盘

**症状**：智谱 `baseUrl = https://open.bigmodel.cn/api/paas/v4/` 点「测试连接」返 `HTTP 404`。

**根因链**：
1. `src/shared/templates.ts:zhipu` 写的是 `adapter: 'openai-compatible'`、`baseUrl: 'https://open.bigmodel.cn/api/paas'`（**末尾少 /v4**）
2. `src/main/adapters/index.ts:openai-compatible → openaiAdapter`
3. `src/main/adapters/openai.ts:openaiAdapter.fetchQuota` **无条件打 OpenAI 专属** `${base}/v1/dashboard/billing/subscription`
4. 智谱 open.bigmodel.cn **根本没有这个端点** → 404

**附加坑**：用户填的 baseUrl 末尾带了 `/v4/`，adapter 拼 `/v1/dashboard/...` 时变成 `https://open.bigmodel.cn/api/paas/v4//v1/dashboard/...`（双斜杠），部分网关直接 404。

**真凭据实测**（2026-10-11，curl `Authorization: Bearer test`）：
- `https://open.bigmodel.cn/api/paas/v4/chat/completions` → 401（路由存在，需鉴权） ✅
- `https://open.bigmodel.cn/api/paas/v4/api/monitor/usage/quota/limit` → 200 `{success:false, code:401, msg:"令牌已过期..."}` ✅（业务码 401，HTTP 200）

## 补完（2026-10-11 后续轮次）

### quota_type ↔ currency 映射 bug 修复

**症状**：orchestrator 写 snapshot 时 `quota_type` 字段**永远存 `'usd'`**（来自 `snapshots.insert` 默认值），导致智谱 TOKEN 维度 / DeepSeek CNY 维度的快照在 SQLite 里都被错误标记为 `usd`，后续任何按 `quota_type` 过滤的逻辑（趋势分析、按维度统计、CSV 导出）都会把不同维度的数字混到一起。

**根因**：`orchestrator.collectAndStore` 没传 `quota_type`，`SnapshotStore.insert` 兜底成 `'usd'`。

**修复**：`src/main/collect/orchestrator.ts` 由 `usage.currency` 推导 `quota_type`：
- `TOKEN` → `'token'`
- `USD` → `'usd'`
- `CNY` → `'credit'`
- 兜底 `'usd'`

**新增单测**：`tests/unit/quota-currency-mapping.test.ts`（3 例）—— 端到端走 `RefreshOrchestrator.refreshOne` + stubbed `globalThis.fetch`，验证写入 DB 的 `quota_type` 和 `currency` 配对正确（智谱 TOKEN、DeepSeek CNY、OpenAI USD）。

### 数值格式化扩展

`DashboardPage.fmtMoney` 新增 `TOKEN` / `COUNT` 维度的 `M/k` 自动单位显示：
- `21,200,000 TOKEN` → `21.20M`
- `12,345 TOKEN` → `12.3k`
- `892 TOKEN` → `892`
- USD / CNY 维持原样（带 `$/¥` 前缀 + 两位小数）

避免智谱配额在 Dashboard 上以裸数字显示（如「已用 21200000 / 40000000」），可读性提升。

### Dashboard 货币维度徽章

新增 `currencyBadge(currency)` helper + `.tag-dim` CSS 变体（USD 绿 / CNY 橙 / TOKEN 紫 / COUNT 青），在每张 ProviderCard 标题旁渲染徽章，`TodayOverview` 概览行同样显示。

效果：用户一眼区分智谱（TOKEN）vs DeepSeek（CNY）vs OpenAI（USD）的卡片，避免「21200000」是美元还是 token 的歧义。

**新增测试**：`tests/unit/renderer/dashboard.test.tsx`（3 例）—— USD/CNY/TOKEN 三维度 + COUNT 中文标签 + 未知 currency 兜底。

### Dashboard 按 currency 分桶汇总

**症状（修复前）**：当 Dashboard 同时存在 OpenAI（USD）、DeepSeek（CNY）、智谱（TOKEN）三种维度的 provider 时，顶部「汇总：已用 $21 / 剩余 $37」**实际上把三个维度简单相加**（21M token + $21 + ¥21 ≈ 21000042），且 `summary.currency` 取 `views[0].currency`——用户看到的「$」完全误导，数字本身也是荒诞的。

**修复**：
1. `DashboardUsage` 类型新增 `byCurrency: Array<{ currency; used; remaining; total; provider_count }>`
2. `orchestrator.dashboardUsage` 按 `v.currency` 分桶独立聚合，按 currency 字母序排序
3. `service.dashboardUsage` 委托 `orchestrator.dashboardUsage`（去掉重复 dead code）
4. `DashboardPage` 顶部汇总改为按桶渲染：每桶一个 `.tag-dim` 徽章 + `已用 / 剩余` 数字 + provider_count > 1 时显示「N 个」注脚
5. 保留 `summary` 兼容字段（旧客户端/导出逻辑仍可工作）

**新增测试**：
- `tests/unit/orchestrator.test.ts`：构造 USD + CNY + TOKEN 三 provider（TOKEN 由手动录入注入），验证 byCurrency 三桶独立，USD 桶 (12.34+37.66) ≠ TOKEN 桶 (21200000+18800000)
- `tests/unit/renderer/dashboard.test.tsx`：2 例 —— 多 currency 渲染 + provider_count 注脚
