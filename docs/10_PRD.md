# 10 PRD

> Template v2

## 背景

- LLM 开发者同时使用多家厂商（OpenAI、Anthropic、Azure、Web 版 Claude/ChatGPT/Gemini 等），各厂商配额、用量、告警信息散落在不同控制台，缺乏统一面板。

- 大量小厂商或 Web 控制台未提供官方用量 API，传统爬虫方案需要逐家手写选择器与坐标，维护成本高且易失效。

- 现有 OCR 抓取普遍要求手填 `x,y,w,h` 像素坐标，页面改版即失效，用户体验差；本地化、隐私安全也是开发者强诉求。

- 需要一款纯本地、可视化、低运维的桌面端工具，把 API 用量与网页抓取（含 DOM / OCR）结果统一收纳在本地 Dashboard。

## 目标

- 提供桌面端（Electron）统一 Dashboard，集中展示每个 LLM 服务商的「已用 / 剩余额度、告警、历史趋势」。

- 内置主流厂商 API 适配器（OpenAI / Anthropic / Azure OpenAI），同时通过 Electron BrowserView + DOM/PaddleOCR-js 覆盖无官方 API 的厂商。

- 产品记忆点：在 BrowserView 当前页面上叠加可视化拖拽框选 UI，所见即所得完成 OCR 截图区域配置，所选坐标自动落库复用。

- 采集失败提供红字提示，兜底支持 ≤3 次点击手动录入本周期已用量并生成有效快照参与告警与趋势。

- 所有数据（配置、Cookie、用量快照）仅保存在本地 SQLite，不上传任何外部服务器。

## 范围

- 平台：基于 Electron 的桌面应用（Windows / macOS / Linux），Expo Web 作为静态 UI 嵌入主窗口。

- 适配层：API 适配器（V1.0 固定 OpenAI / Anthropic / Azure OpenAI）+ Web 抓取（BrowserView + DOM 脚本 + PaddleOCR-js）。

- 数据存储：本地 SQLite 数据库（providers、provider_params、llm_usage_snapshots、settings 等表）。

- 触发方式：仅手动点击【全部刷新】/【单条刷新】，无任何后台定时或自动轮询。

- 容量：单实例舒适支持 ≥20 个服务商，硬上限 30 个 BrowserView。

- 不在范围：云端同步、多人协作、移动端、深度学习训练用量统计（仅做面板展示）。

## 术语

- Provider / 服务商：单个 LLM 厂商或厂商下的某条配置记录（含多账号/多配额并行）。

- Snapshot / 快照：某次成功采集生成的用量记录行（已用、剩余、时间戳、来源）。

- BrowserView：Electron 内嵌浏览器视图，每个 Web 抓取 Provider 独立持有一个会话。

- DOM 抓取：在 BrowserView 内执行预配置脚本片段读取页面文本以提取用量数字。

- OCR 抓取：基于本地 PaddleOCR-js 识别 BrowserView 截图区域中的数字。

- 选区 UI：叠在 BrowserView 当前页面上、用于鼠标拖拽框选截图区域的可视化层。

- 有效快照：采集成功或手动录入产生的快照，参与告警与趋势；失败快照不入库。

## 用户故事

- 作为多 LLM 用户，我希望在一个 Dashboard 看到所有服务商的已用/剩余额度，省去逐个登录查面板。

- 作为无官方 API 的厂商用户，我希望通过 Web 抓取模式接入，且能用鼠标拖框配置 OCR 区域，无需手填坐标。

- 作为配置维护者，我希望同一服务商可配置多条记录（多账号/多配额），互不干扰。

- 作为被风控困扰的用户，我希望全部刷新时分批并行、间隔可调，避免被目标站识别为爬虫。

- 作为隐私敏感用户，我希望所有登录态与用量数据都只存在本地，绝不上传。

- 作为抓取失败的用户，我希望红字明确提示原因，并能在 ≤3 次点击内完成手动录入兜底。

## 功能需求

- 服务商配置 CRUD：新增、编辑、删除、启用/禁用 LLM 服务商配置，持久化到本地 SQLite；同一服务商支持多条记录并行（独立 BrowserView、登录态、快照）。

- 采集模式选择：每条服务商可独立选择 `api` 或 `web_crawl`；`web_crawl` 下二选一 `dom` 或 `ocr` 并保存对应参数。

- API 适配器：V1.0 内置 OpenAI / Anthropic / Azure OpenAI 三家固定适配器，按配置调用用量接口生成快照。

- Web 抓取会话：每个 Web 抓取 Provider 对应独立 BrowserView 会话，Cookie 与登录态本地持久化。

- DOM 提取：仅执行预配置脚本片段读取页面文本，不注入不可信远程脚本。

- OCR 选区可视化拖拽（产品记忆点）：OCR 模式下在 BrowserView 当前页面上叠加选区 UI，用户可像截图工具一样所见即所得拖框，实时高亮、所选坐标自动回填并落库为持久化参数，一次配置终身复用。

- OCR 识别：基于本地 PaddleOCR-js 运行，不依赖外部云端识别服务；识别结果置信度低于配置阈值时判定为抓取失败，不生成错误快照。

- 登录检测：检测到 Provider 页面未登录时该行显示红色「🔐 请手动登录」，弹窗 BrowserView 供用户登录，登录成功后自动隐藏并复用会话。

- 失败提示：任意采集环节失败时该行显示红色「⚠️ 抓取失败」，历史快照保持不变。

- 快照生成与告警：采集成功后自动计算剩余额度并写入 `llm_usage_snapshots` 表；剩余额度 ≤ 告警阈值时该行以红色背景/状态提示。

- 手动录入兜底：抓取失败或未登录时支持手动输入本周期已用量，提交后生成有效快照并参与告警与趋势；全流程 ≤3 次鼠标点击完成。

- 趋势图：Dashboard 支持单服务商历史用量趋势图（已用/剩余双曲线），仅展示有效快照，时间范围可筛选。

- 手动刷新：所有采集仅由用户点击【全部刷新】/【单条刷新】触发，无任何后台定时/自动轮询；【全部刷新】点击后置灰 10 秒。

- 刷新策略：全部刷新时执行策略符合配置（并行/串行/分批可设定），默认并发 5 个/批，可调整 1~10，相邻 Provider 刷新间隔 ≥N 秒以规避风控；同一 Provider 两次刷新间隔 <60 秒则直接跳过并提示「操作过于频繁」。

- 本地存储：所有登录态、Cookie、配置数据、用量快照均保存在本地 SQLite，不上传外部服务器。

- 容量与性能：单实例同时驻留 BrowserView 在 20 个以内时体验流畅，硬上限 30 个。

- 主进程 IPC 校验：Expo Web 仅作为静态 UI 嵌入 Electron，所有数据库 / BrowserView / OCR 操作必须经主进程 IPC 校验。

## 交互与状态

- 服务商配置管理：入口 Dashboard 顶部【服务商】按钮 → 配置面板；交互 列表行点击【编辑】打开表单，字段含名称、模式、子模式、参数、告警阈值、启用开关；空态 列表为空时显示「尚未配置任何服务商，点击右上角 + 新增」并提供主操作按钮；错误态 必填校验失败时字段下方红字提示，保存失败弹 Toast。

- 采集模式选择：入口 编辑表单中的「采集模式」下拉；交互 切换 `api` / `web_crawl` 联动切换下方参数区（API 显示密钥/Endpoint，Web 显示 DOM 选择器或 OCR 选区按钮）；空态 子模式未选择时参数区显示「请先选择采集模式」占位；错误态 不支持组合（例如 ocr 模式下未配置坐标）时保存按钮置灰并提示。

- OCR 选区可视化拖拽：入口 OCR 配置项右侧【框选区域】按钮；交互 弹出对应 Provider 的 BrowserView，叠加选区 UI，鼠标拖拽矩形实时跟随并高亮，松开后自动计算并回填坐标；空态 尚未框选时显示「请在页面上拖拽框选数字区域」提示；错误态 选区过小或超出视口时拒绝保存并红字说明。

- 登录检测与提示：入口 Provider 行右侧状态徽标；交互 识别到未登录后红字显示「🔐 请手动登录」，点击该行展开 BrowserView 完成登录，登录成功回调自动隐藏 BrowserView 并刷新该行状态；空态 已登录会话下不显示提示；错误态 会话超时或 Cookie 失效时回到「🔐 请手动登录」。

- 采集失败提示：入口 Provider 行状态徽标；交互 任意采集环节失败后红字显示「⚠️ 抓取失败」并保留历史快照；空态 尚未刷新过的 Provider 显示「—」；错误态 失败原因（超时/选择器未命中/置信度低/限流）在 Tooltip 展示。

- 快照生成与告警：入口 Provider 行背景与状态徽标；交互 采集成功计算剩余额度后写入快照表，剩余 ≤ 阈值时整行红色背景 + 告警图标；空态 当前周期无快照时显示「暂无数据」；错误态 写入失败时弹 Toast 并保留原状态。

- 手动录入兜底：入口 Provider 行【手动录入】按钮（失败/未登录时高亮）；交互 弹窗输入本周期已用量 → 确认 → 生成有效快照并刷新行；空态 无（按钮始终可点）；错误态 输入非数字或负值时表单校验拦截。

- 趋势图查看：入口 Provider 行【趋势】按钮或 Dashboard 侧栏；交互 打开趋势弹窗，显示已用/剩余双曲线，提供时间范围筛选（7d/30d/自定义）；空态 无有效快照时显示「暂无趋势数据」与引导按钮；错误态 数据加载失败显示「图表加载失败，点击重试」。

- 全部/单条刷新：入口 Dashboard 顶部【全部刷新】与每行【刷新】；交互 点击后调度队列执行采集（分批并行、间隔 N 秒），全部刷新按钮置灰 10 秒；空态 无可刷新 Provider 时按钮置灰并提示「请先启用至少一个服务商」；错误态 同 Provider <60s 重复刷新时跳过并 Toast「操作过于频繁」。

- 设置与刷新策略：入口 Dashboard 顶部【设置】；交互 表单编辑并发数（默认 5，范围 1~10）、相邻 Provider 刷新间隔、告警阈值默认值；空态 默认值已预填；错误态 输入越界时校验拦截并红字提示。

## 模块划分（Epic 候选）

- 服务商配置中心：负责 Provider 记录的 CRUD、模式/子模式选择、参数持久化与多账号并行管理。

- 采集执行引擎：负责 API 适配器调用、BrowserView 会话管理、DOM 脚本执行、OCR 抓取调度与分批并行策略。

- OCR 可视化选区：负责在 BrowserView 上叠加选区 UI、实现拖拽框选、坐标回填与持久化（产品记忆点核心模块）。

- 快照与告警服务：负责快照落库、剩余额度计算、阈值告警、手动录入兜底（≤3 点击）与趋势图数据查询。

- 本地存储与 IPC 网关：负责 SQLite 表结构、所有数据库/BrowserView/OCR 操作的主进程 IPC 校验与本地化约束。
